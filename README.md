# 🎾 모두의테니스클럽(MTC) — 코인전·클럽관리 시스템

**Play Together. Grow Together. MTC.**

모두의테니스클럽(MTC)의 출석, 자동·수동 대진, 코인전 승패, 경기 스코어, 실력 레이팅, 코인 지급·차감, 대출 및 변경 이력을 한곳에서 관리하는 웹앱입니다. 회원들이 같은 기록을 확인할 수 있도록 GitHub Pages와 Firebase Firestore를 사용합니다.

- **운영 사이트:** https://cojumkr.github.io/moduetennis/
- **GitHub 저장소:** https://github.com/cojumkr/moduetennis
- **현재 버전:** v64 — 명예의 전당 1·2·3위 글자 크기 차등 표시

## 1. 클럽 코인전 소개

클럽 코인전은 실제 경기의 승패에 따라 코인을 얻거나 잃는 친선 리그입니다. 반기(상·하반기) 단위로 운영하며, 회원별 코인 잔액과 대출액을 함께 확인할 수 있습니다.

| 항목 | 운영 방식 |
| --- | --- |
| 시즌 | 상반기 / 하반기 |
| 시작 코인 | 기본 3개. 신규·전환 회원은 실제 지급 여부를 확인하고 수동 지급 가능 |
| 단식 | 승자 +1개 / 패자 -1개 |
| 복식 | 승리팀 선수 각각 +1개 / 패배팀 선수 각각 -1개 |
| 출석 코인 | 조건을 충족한 실제 참석 회원에게 날짜별 +1개 별도 지급 |
| 수동 조정 | 회원별 +1 / -1, 사유 기록 및 취소 |
| 대출 | 코인 부족 시 대출 기록 및 취소 관리 |
| 순위 | 보유 코인에서 누적 대출을 차감한 값 기준 |

**주의:** 출석 코인은 토요일 사전 투표 참석 대상자 중 실제 출석한 회원에게 지급하는 운영 원칙입니다. 현재 앱은 실제 출석 여부와 중복 지급은 확인하지만 **투표 참석 대상자 여부를 자동 검증하지는 않습니다.** 운영자가 지급 전에 확인해야 합니다.

## 2. 주요 기능

### 📅 출석·회원·게스트 관리

- 날짜별 회원 출석 체크 및 과거 모임 날짜 조회
- 회원별 NTRP 설정 및 활동 상태 확인
- 게스트 등록, 게스트 NTRP 지정, 게스트 코인 관리 및 퇴장
- 게스트의 정회원 전환: 기존 게스트 경기 기록은 유지하고 신규 정회원 계정 생성
- 누락 회원 보완(고영훈 회원 추가 버튼; 이미 등록된 경우 중복 방지)

### 🎾 경기 편성 및 승패·스코어 기록

- 2면 기준 자동 대진: 참여 횟수, NTRP, 파트너 반복 등을 고려
- 단식(1:1), 복식(2:2) 지원
- 현장 화이트보드 대진이나 과거 경기를 수동으로 등록
- A팀/B팀 **실제 게임 스코어** 입력(예: 6:3) 및 승리팀 확정
- 승패 확정 시 코인 자동 정산
- 완료 경기의 **점수 수정**: 기존 승리팀을 유지하는 범위에서 점수 변경
- 수정 전후 스코어와 수정 시각을 경기 데이터에 기록
- 승리팀 자체가 바뀌는 수정은 점수 수정 기능에서 지원하지 않음

### 📈 MTC 실력 레이팅

- 모든 회원 **5.00**에서 시작하는 MTC 내부 실력 지표
- Elo 방식을 응용하여 상대 팀 레이팅과 경기 승패를 반영
- 스코어가 있으면 게임 점수 차이도 레이팅 변동에 반영
- 복식은 팀 레이팅을 이용하여 선수별 점수 변동 계산
- 개인별 레이팅, 승·패, 승률, 경기별 레이팅 변동 표시
- 과거 승패만 있는 경기는 스코어 가중치 없이 계산
- 과거 스코어를 수정하면 경기 순서에 따라 레이팅을 다시 계산

**MTC 레이팅 5.00은 공식 NTRP 5.0과 다릅니다.** NTRP는 대진 편성용 실력 설정이고, MTC 레이팅은 코인전 결과를 바탕으로 계산되는 내부 지표입니다.

### 🪙 코인 지급·차감 및 대출

- 회원별 **+1 / -1** 버튼으로 코인 조정
- 수동 조정 시 사유 입력, 날짜별 정산 기록 저장
- 출석 코인 +1 지급 및 지급 취소
- 코인 대출 지급 및 대출 취소
- 취소 가능한 정산은 취소 표시를 남겨 이력 확인

## 3. 모든 기록을 한눈에 — 전체 코인전 기록

사이트의 **📜 전체 코인 기록** 메뉴에서 특정 날짜를 일일이 선택하지 않고 모든 날짜의 기록을 최신순으로 확인할 수 있습니다.

**① 🎾 승패 기록 — 가장 위에 표시**

- 경기 날짜, 참가 선수, A/B팀, 스코어, 승리팀
- 이미 입력한 경기의 점수 수정 및 관련 이력
- 취소된 경기 여부 확인

**② 🪙 출석 코인 및 기타 지급·차감**

- 날짜별 출석 코인 지급
- 회원별 수동 코인 +1/-1 및 입력 사유
- 취소된 지급·차감 내역

**③ 📒 대출 기록**

- 회원별 대출 날짜 및 수량
- 취소된 대출 내역

별도로 **📒 대출·정산** 메뉴에서는 선택한 날짜의 정산과 시즌 코인 현황을 확인할 수 있습니다.

> 초기 버전에서 자동 지급된 시작 코인 3개 등은 개별 거래 로그가 없을 수 있습니다. 과거에 없던 로그를 임의로 생성하지 않습니다.

## 4. 실제 사용 순서

1. **날짜 선택** — 클럽데이 또는 과거 경기 날짜 선택
2. **출석 체크** — 참석 회원과 게스트 등록
3. **대진 생성** — 자동 배정 또는 수동 등록
4. **스코어·승패 확정** — A/B팀 점수 입력 후 승리팀 선택
5. **코인 정산 확인** — 승자 +1, 패자 -1 자동 반영
6. **추가 코인 관리** — 출석 코인, 수동 조정, 대출 처리
7. **전체 기록·레이팅 확인** — 승패, 지급·차감, 대출 이력 및 개인별 실력 점수 조회
8. **오입력 정정** — 완료 경기에서 점수 수정(승리팀 유지), 필요 시 정산 취소
9. **백업** — 하단에서 전체 기록 JSON 다운로드

## 5. 데이터 저장·보존과 주의사항

- **웹사이트 파일:** GitHub Pages의 `index.html`
- **운영 데이터:** Firebase Firestore (`clubs/mtc`)
- **접속 방식:** 익명 Firebase 인증 기반 공동 편집
- **백업:** 전체 기록 JSON 파일 다운로드 지원

`index.html` 교체만으로 Firestore의 기존 데이터가 삭제되지는 않지만, **새 코드의 오류나 잘못된 저장으로 데이터가 덮어써질 위험은 있습니다.** 업데이트 전 반드시 데이터를 백업하고, 배포 후 기존 날짜의 경기·코인 잔액이 유지되는지 확인하세요.

**보안:** 별도 로그인·권한 구분이 없는 공동 편집 구조입니다. 링크를 아는 사람이 기록을 수정할 수 있으므로 외부 공개 및 민감정보 입력에 주의하세요. 백업 JSON 파일은 공개 GitHub 저장소에 업로드하지 마세요.

**검증 범위:** 실제 Firebase 환경에서 모든 기기·동시 편집·복구 동작까지 검증된 제품은 아닙니다. 중요한 기록은 별도 백업을 보관하세요.

## 6. GitHub 배포·업데이트 방법

1. GitHub 저장소 `cojumkr/moduetennis` 접속
2. 저장소 최상위의 `index.html`을 새 버전으로 교체
3. `README.md`도 최신 설명서로 교체
4. **Commit changes** 클릭
5. GitHub Pages 배포 후 사이트에서 새 버전 표시 확인
6. 브라우저에서 `Ctrl + Shift + R`로 새로고침
7. 이전 경기 기록, 코인 잔액, 전체 이력, 레이팅 표시 점검

`README.md`는 설명 문서이므로 수정해도 Firebase의 경기·코인 기록을 변경하지 않습니다.

## v24 변경 이력 — 자동 대진 2코트 동시 편성

- 복식 출석자 8명 이상, 빈 코트 2개일 때 한 번의 클릭으로 두 코트에 4명씩 편성합니다.
- 당일 경기 횟수가 적은 선수부터 8명을 선발하고, 두 코트의 NTRP 팀 균형과 파트너 중복을 함께 고려합니다.
- 진행 중인 경기의 코트와 선수는 중복 배정하지 않습니다.
- 출석자 4~7명이면 1코트, 8명 이상이면 2코트가 기본입니다(코인 1개 이상, 미참여 상태 등 조건 충족 시).
- 기존 Firebase 기록, 코인, 승패, 스코어 및 레이팅은 초기화하지 않습니다.


## v24 — 전체 기록에서 경기 결과 수정

- **전체 코인 기록 → 승패 기록**에서 `점수 수정` 또는 `승패·점수 수정`을 선택합니다.
- `승패·점수 수정`에서는 `6:3` 형식으로 점수를 입력하면 승리팀이 자동 결정됩니다.
- 승리팀이 바뀌면 기존 승리팀 각 -2코인, 기존 패배팀 각 +2코인으로 정산을 바로잡고 승패 통계와 레이팅을 재계산합니다.
- 기존 승리팀의 코인이 2개 미만이면 음수 잔액 방지를 위해 승패 변경을 차단합니다.
- `resultEdits`에 이전 결과와 수정 시각을 보존합니다. 기존 데이터 저장 경로는 유지합니다.
- 실제 Firebase 다중 사용자 환경에서 테스트하기 전, 전체 JSON 백업을 내려받으세요.


## v27 — 경기 결과 시각화 개선
- 전체 코인 기록 및 날짜별 완료 경기에서 A팀/B팀을 좌우 카드로 표시합니다.
- 승리팀은 녹색 강조, 트로피 및 승리 배지, 패배팀은 회색 배지로 구분합니다.
- 게임 스코어를 크게 표시하고, 스코어 미입력인 과거 기록은 대시(–)로 표시합니다.
- 점수 수정 / 승패·점수 수정 기능을 유지합니다.
- Firebase 데이터 구조와 코인 정산 로직은 변경하지 않습니다.


## 📊 출석 순위 (v27)
- **출석 순위** 탭에서 클럽원별 실제 출석 체크 횟수를 순위별로 확인합니다.
- 전체 기간 / 선택 날짜의 반기 / 선택 날짜의 연도별 집계를 제공합니다.
- 출석 코인 지급 횟수와 **별도**로 집계하며, 동일 날짜의 출석은 1회만 인정합니다.
- 게스트는 제외하며, 휴회·탈퇴 회원의 과거 출석도 보존합니다.
- 기존 Firestore `sessions[날짜].attendance` 기록을 읽기만 하므로 기존 코인·승패·레이팅 데이터에 영향을 주지 않습니다.
- 출석 체크가 저장되지 않은 과거 날짜는 집계할 수 없습니다.
